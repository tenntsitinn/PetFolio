# 单屏 DPI 拖动修复

范围：单屏幕上启动时的显示缩放，以及运行中修改缩放。当前换算使用单屏桌面原点；混合 DPI 多屏的原点映射不在本次范围内。

## 坐标约定

- Codex 保存的位置和配置宽度保留为原始 DIP。
- PetState 发布的位置、尺寸、鼠标坐标和拖动边界统一为物理像素。
- 位置与尺寸使用 `round(dip * dpi / 96)`，中点向远离零的方向舍入。
- 鼠标位移已经是物理像素，不重复缩放。
- 宠物底部的 8 DIP 间距与 32 DIP 控制栏也转换为物理像素。

## 动态更新

发现宠物 HWND 后通过 GetDpiForWindow 获取 DPI。气泡收到 WM_DPICHANGED 或 WM_DISPLAYCHANGE 时，通知跟踪服务排队刷新；退出窗口消息处理后再更新状态，避免同步布局重入。现有跟踪循环也检查宠物窗口 DPI，覆盖气泡隐藏、通知时序不同等情况。鼠标按下和松开时同样检查，避免使用上一次定时器留下的旧命中区域。

查询返回零时保留上次有效 DPI。配置未修改也会重新计算物理坐标，不依赖配置写入通知。拖动中切换 DPI 会转换实时位置并以当前鼠标位置重建拖动起点；松手后的落盘等待仍保留原有期限，起始保存坐标从原始 DIP 重新计算，避免舍入误差提前结束等待。

屏幕边界沿用每次 MoveDrag 读取的 Screen 工作区及屏幕范围。位置发布后由气泡原有布局处理避让和方位选择。

## 自动与人工验证

`test.ps1` 中的 PetDragTests 覆盖 DPI 换算、物理鼠标增量、拖动中切换、松手等待期间切换及底部限制；PetTrackingTests 使用可控 DPI 查询，验证启动、轮询和通知更新、配置未写入时刷新、查询失败及反复切换的舍入行为。这些模拟 DPI 测试不替代真实 Windows 缩放验收。

单屏人工验收：

1. 分别在 100%、125%、150%、175%、200% 下启动，连续拖动宠物，确认气泡立即跟随。
2. 保持应用运行，依次切换 100% → 125% → 150% → 100%，确认尺寸、命中与位置自动恢复，无需重启。
3. 在 125% 下测试宠物宽度 80、112、224，检查主体点击与底部拖动边界。
4. 快速拖动、松手后再次拖动，确认没有等待旧配置造成的回跳；缩放切换后重复此操作。
5. 隐藏气泡、修改缩放再显示，确认显示时使用新 DPI。

运行日志的 `pet-dpi` 事件记录检测到的旧、新 DPI，可用于现场核对。
