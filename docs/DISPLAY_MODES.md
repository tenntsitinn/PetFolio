# 显示模式路由

2026-10-20。路由依据当前启用的桌面输出，而不是连接的显示器数量，也不依赖 quota 查询。

## 判别与坐标

`WindowsPetDesktop.ReadMode` 使用 `QueryDisplayConfig(QDC_ONLY_ACTIVE_PATHS)`，以 adapter LUID + source ID 标识桌面源：

| 当前启用路径 | 路由 | 坐标处理 |
| --- | --- | --- |
| 一个输出 | Single | 单屏；仅电脑屏幕与仅第二屏幕均使用此路径 |
| 多个输出共用一个源 | Duplicate | 一个桌面坐标空间 |
| 多个输出各有独立源 | Extended | 既有多屏相邻关系与 DPI 映射 |
| 多源且其中有源供多个输出使用 | Mixed | 合并镜像桌面后，保留扩展部分 |

未启用的物理输出不参与判别。复制模式通常只需消费系统提供的一个桌面区域；若枚举产生重复区域，仅在复制／混合模式已确认且物理范围、工作区和 DPI 完全一致时合并，优先保留主屏代表。不同 DPI 或工作区的重叠记录仍拒绝猜测。

原生 API 的缓冲区大小查询与读取之间遇到配置变化（ERROR_INSUFFICIENT_BUFFER）最多重试三次。输出源数量与枚举到的去重桌面数量不一致时，按切换中的暂态失败处理。CCD 不可用或拒绝访问时保留既有几何路径，但不会把未知重叠自行认作复制模式。

依据：[Microsoft QueryDisplayConfig 文档](https://learn.microsoft.com/en-us/windows/win32/api/winuser/nf-winuser-querydisplayconfig)。只读当前 active paths，不查询所有可能的连接组合，不更改 Windows 显示设置。

## 刷新与开销

- 启动时读取一次。
- `WM_DISPLAYCHANGE`、`WM_DPICHANGED`、`SPI_SETWORKAREA` 或目标宠物窗口改变时刷新；同一批排队通知合并。
- 正常快照缓存 30 秒作为漏通知兜底；读取失败每秒重试。
- 动画和拖动复用快照，不为每帧重复读取显示配置。
- quota 的五分钟网络刷新与显示路由独立，停用 quota 不会停用已有跟踪服务的显示检测。

原有外部宠物窗口 DPI 查询仍用于及时发现缩放变化；这里的 30 秒指完整拓扑查询与显示器枚举，不是所有 Win32 调用的频率。模式改变会清除旧拖动预测，并记录 `pet-display-mode`。保存位置仍指向旧桌面时继续等待 Codex 更新，不主动移动宠物或写宿主状态。

## 验证范围

纯逻辑测试覆盖单屏、复制、扩展、混合、跨显卡 source ID、镜像合并、冲突拒绝；跟踪集成测试覆盖通知合并、30 秒缓存，以及 Single → Duplicate → Extended 切换。原生测试检查结构 ABI 并只读当前实际模式。

本机本轮原生读取返回 Single、一个源、一个桌面；单次模式查询约 3.5–5.7 ms，仅为本机抽样，不代表所有驱动。复制模式和混合模式使用注入数据验证，仍需用户在 Win+P 切换及不同显示器配置下实机验收。
